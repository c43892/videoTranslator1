## Images and source

`engine/` captures the currently running, patched engine. Its 18 original Python
modules match the local runtime after normalizing line endings and trailing blank
lines at capture time. The new `cloud_control.py` and `cloud_worker.py` are separate
entrypoints. The subsequent provider change adds a configurable tokenizer read
timeout: cloud uses 600 seconds for Files-backed model reloads; local stays at 120.

Build context is generated by `python deploy/azure-jp/prepare-build.py`. Only
allowlisted source directories are included; `.env`, secrets, user media, SQLite
databases and local model files are excluded.

- `Dockerfile.control`: CPU web application, FFmpeg, Blob identity libraries and
  the JavaScript runtime required by yt-dlp. No Docker socket or Docker CLI.
- `Dockerfile.engine`: private CPU control API or GPU-side orchestration process.
- `Dockerfile.tts`: local packaging validation based on the frozen local image.
- `Dockerfile.tts-source`: rebuild from upstream commit
  `830f6f8f94a51fea23ab1d639027a86200075a4e` and `tts-requirements.lock`, exported
  from the validated runtime. This supports ACR builds without uploading gigabytes
  of dependencies from the developer machine.
- `Dockerfile.tts-pinned`: pins auxiliary model revisions to the local model cache.
  Text-normalizer and Numba caches use writable directories under `/tmp`.

All new runtime images use UID 10001. The GPU container must be first in ACA.

## CPU persistence and private control

`compose.cpu.yml` requires generated environment files under a private deployment
directory. Never commit them. SQLite, inspection workspace and PostgreSQL data stay
on the VM block disk. `/mnt/videotranslator-data` must be the Azure Files `data`
share, mounted with UID/GID 10001 and restrictive ownership. The GPU mounts the
same share at `/data`; model files use the separate `models` share.

Use `engine.env` for the worker database URL, private API bearer token and external
provider credentials. `studio.env` contains **only sandbox Stripe keys**, the cloud
webhook signing secret, Firebase web configuration and the same private API token.
Mount Firebase Admin credentials read-only. Assign Blob Data Contributor to the
CPU managed identity and AcrPull to the CPU/GPU identities. Registry admin password
authentication stays disabled.

The CPU profile runs its outbox dispatcher, payment inbox and result reconciler
even while GPU replicas are zero. Private `/health` checks only the control database;
webpage health never wakes a GPU. GPU work is represented by PostgreSQL rows and the
read-only `gpu_runnable_work` view. The cloud worker polls this durable queue while
holding the same deployment-wide advisory lock used by the existing engine. This
cloud-only entrypoint removes the need for a separate Redis/Celery broker on the
CPU VM; the local Celery deployment is unchanged.

The scaler role must have SELECT only on `gpu_runnable_work`. The worker needs SELECT
and UPDATE on `jobs` and `cloud_executions`; schema creation belongs to control.
PostgreSQL accepts TLS only for network connections. Permit port 5432 at the NSG
only from the ACA subnet and the CPU host, never from the public internet.

## Validation admission and lifecycle

Admission is disabled by default (`GPU_STARTS_ENABLED=false` and
`CLOUD_ACCEPT_JOBS=false`). For automatic task processing, explicitly set both to
`true` in the private `.env`, and set `CLOUD_VALIDATION_MAX_JOBS=0` to disable the
lifetime validation-attempt counter. This does not disable the web's daily/monthly
cost admission checks, single active GPU job limit, or engine execution deadline.
To pause new admissions, set both switches to `false` and recreate web/control;
already submitted GPU work is allowed to finish. Initial validation limits
are one admitted job and a maximum 1800-second deadline, including GPU startup.
The attended validation override permits three cumulative attempts to cover the
sample correction and cloud model-reload timeout fix; this is not production capacity.
The PostgreSQL view excludes expired jobs even when control/worker is down. Running
and cancellation-pending work remains counted until terminal or expired.

Every request gets a unique execution directory. A worker crash fails that attempt
closed; a user retry uses a new attempt and directory. A stale process cannot
publish a completed result after the deadline or cancellation. Results are copied
to generation-specific Blob keys, decoded and checked, and a publication manifest
is written last. CPU export does not keep the GPU awake.

`gpu.template.json` is a configuration template, not a deployable document until
digests, private database credentials and provider secrets are supplied. It has no
public GPU ingress, min=0/max=1 and a PostgreSQL scaler. Configure Blob CORS for the
exact HTTPS website origin and PUT/GET/HEAD/OPTIONS; include `x-ms-*`/Content-Type
headers. Browser uploads use 4 MiB blocks with bounded retries and SAS renewal.

`validate-gpu.py IMAGE@sha256:DIGEST` performs a separate B0 model-start test with
one T4 and a 25-minute limit. It deactivates test revisions and resets min replicas
to zero in `finally`. Review `vt-data/azure-tmp/gpu-validation-result.json` and the
actual Azure revision state afterwards; errors require immediate cleanup.

Budget alerts are not spending caps. The authorized US$20 is a validation budget,
not approval to keep a CPU VM running indefinitely. The review website is time-bounded
by the configured VM auto-shutdown. Admission settings must reflect the explicitly
authorized operating window; changing the defaults alone does not pause a deployment
whose private `.env` explicitly enables them.
Verify deallocation when the review window ends. Disk, registry and stored model
charges continue independently of GPU/VM compute.

  deadline, cancellation and artifact path isolation.
